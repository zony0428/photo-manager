# UI/UX デザインシステム & Tiat 志向設計ガイドライン (v3.00 標準)

本ドキュメントは、Photo Manager v3.00 で確立された「脱・芋UI（Stoic Darkroom / Tiat-Inspired Design System）」の視覚ルール・レイアウト構造・ドキュメント編集規約を定義するナレッジアイテム（KI）である。
今後の新機能追加・UI改修・ドキュメント更新時は、本ガイドラインを絶対基準として遵守し、過去の「絵文字過多・太枠Box-in-Box・2段ヘッダー・アコーディオン多重スクロール」へ先祖返りさせてはならない。

---

## 1. タイポグラフィ規約 (Typography)

1. **UIフォントからの明朝体（`Shippori Mincho`）完全撤廃**:
   - 業務ツール・写真管理UIのボタン・ラベル・ツリーに明朝体が混入すると、画数の多い漢字が潰れ、視認性とモダンさが著しく損なわれる。
   - `--font-sans` および `--font-display` はすべて端正なサンセリフ体（`'Inter', -apple-system, BlinkMacSystemFont, 'Yu Gothic UI', 'Meiryo', sans-serif`）に統一する。
2. **数値の等幅整列 (`tabular-nums`)**:
   - 写真枚数バッジ、EXIF数値（シャッター速度・F値・ISO・焦点距離）、ヒストグラム階調、日付表示には必ず `font-variant-numeric: tabular-nums` または `--font-mono` を適用し、桁ズレを防ぐ。
3. **文字サイズとウェイトの抑制**:
   - 太字（`font-weight: 700/800`）の乱用を避け、基本ウェイトは `400`〜`500`、アクティブ要素や見出しのみ `600` とする。

---

## 2. アイコノグラフィ & 絵文字パージ規約 (Zero OS Color Emojis)

1. **OS標準カラー絵文字の全面禁止**:
   - Windows のカラー絵文字（`📁`, `🏷️`, `📷`, `🏅`, `⭐`, `⚪`, `🗑️`, `📜`, `🌙`, `🌐`, `⚙️`, `📱`, `❓`, `⏻` 等）をUIのボタン・見出し・ツリー・バッジに直接配置してはならない。
   - カラー絵文字が並ぶと、和紙（Paper）・夜墨（Sumi）のストイックなトーンが崩壊し、写真の色彩知覚を邪魔する。
2. **単色細線SVGアイコン（`stroke="currentColor"`）への統一**:
   - アイコンは `width="15" height="15"`（または `16px`）、`stroke="currentColor" stroke-width="1.75" fill="none"` の単色細線SVGを使用し、テキストカラー（`var(--text-main)` / `var(--text-muted)`）に自動追従させる。
3. **4段階評価（`優 / 良 / 可 / 棄`）のタイポグラフィ表現**:
   - 評価ボタンやバッジに `🏅` `⭐` `🗑️` などの絵文字を添えず、漢字1文字（英語モード時は `Ex / Gd / Nm / Rj`）の端正なピルボタンで表現する。

---

## 3. サーフェス・境界線・サムネイルバッジ規約 (Surfaces, Borders & Badges)

1. **太い黒枠（`#2a2926`）と Box-in-Box の禁止**:
   - 和紙モードで `1px solid #2a2926` のような不透明な黒枠を引くと、画面全体が「黒マジックで囲った帳票」のように重くなる。
   - 境界線は `--border-color: rgba(42, 41, 38, 0.14)`（和紙）／`rgba(255, 255, 255, 0.10)`（夜墨）の繊細な半透明ラインとし、パネルの中にさらに枠線付きボックスを入れ子にする Box-in-Box 構造を作らない。
2. **サムネイル上オーバーレイバッジのモノトーン・すりガラス化**:
   - 写真サムネイル上に載る `.format-badge`（RAW等）、`.stack-badge`、`.xmp-badge` に原色（オレンジ・青・緑のベタ塗り）を使ってはならない。
   - すべて `background: rgba(20, 20, 20, 0.68); backdrop-filter: blur(4px); color: rgba(255, 255, 255, 0.92); border: 1px solid rgba(255, 255, 255, 0.14);` の半透明ダーク・モノトーンに統一し、写真そのものの色を主役にする。
3. **極細スクロールバー（`6px`）の徹底**:
   - メイングリッド・左メニュー・右インスペクタ・モーダル内のすべてのスクロールバーは `width: 6px; height: 6px;` の控えめな丸角バーとする。

## 4. レイアウト & ナビゲーション動線規約 (v3.00+ / v1.4.0+ Layout Architecture)

### 4.1 メインツールバーの完全1段化（高さ `44px`、下部フッター既定／上部ヘッダー切替対応）
- メインツールバー（`.app-header.unified-single-header`, 高さ `44px`）は **1段のみ** とし、既定では画面下部（フッター、`body.toolbar-bottom`）に配置する（設定モーダルで「下部（フッター）」⇄「上部（ヘッダー）」を切り替え可能）。
- 配置順序：
  - **左**: メニュー開閉トグル（`[メニュー]`）＋ アプリタイトル ＋ バージョン番号（`#appVersion`）＋ 表示レイアウト切替（`グリッド / びっしり / マウント`）、`スタック`、`情報`、サムネイルサイズスライダー、ソート順セレクト（※スライドショー再生は左サイドバー `Binder ＞ 保存済みセット` に集約）
  - **中央（常設3大基本フィルタ `.header-center-filters`）**: ①表示対象プルダウン（`すべての写真 / 接続中の写真 / 未接続の写真 / リンク消失の写真 / 未分類の写真 / 重複のある写真`）、②形式・状態プルダウン（`すべての形式 / RAW / RAW+JPEG / JPEG / 調整済 / XMPあり`）、③評価ピル（`優 / 良 / 可 / 棄`）＋ `×` リセットボタン
  - **右**: テーマの明暗トグル（`Tetheract D ⇄ L` / `夜墨 ⇄ 和紙`。4種からの選択は設定モーダル）、言語切替（`JP / EN`）、`設定`、`スマホ連携`、`ヘルプ`、詳細パネル開閉（`詳細`）、`終了`
- 旧2段目ヘッダー（`#viewHeaderChipBar`）は廃止し、アクティブな絞り込み条件は写真グリッド下部に重なるフローティング自然文フィルタフッターバー（`#filterFooterBar`）として表示する（レイアウトシフトゼロ）。

### 4.2 左ペインの2段階構造（垂直タブレール ＋ 全高メニューエリア）
- 左サイドバー（`#sidebar`）は以下の **2段階横並び構造** とする：
  1. **左端：垂直タブレール（`#sidebarRail`, 既定幅 `54px`。右端ドラッグで最大 `108px`）**
     - 上部に `Binder / Folder / Tag / Place / Historia / Gear / Lab` の7タブ、最下部に `Search` タブを配置する。
  2. **右側：全高メニューエリア（`#sidebarStage`）**
     - 選択された1つのセクションだけを **縦100%の高さ** でゆったり表示する（複数アコーディオンの同時縦積みは行わない）。
- **`Binder` ペインの責務（条件セット保存専用ページ）**:
  - `Binder` は「現在の絞り込み条件の組み合わせに名前を付けて保存・呼び出し・スライドショー再生する専用ページ」とし、表示対象・形式・評価フィルタはすべてメインツールバー中央の3大基本フィルタに集約する。
- **メニューオフ時（`is-collapsed`）のオーバーレイ動作**:
  - ヘッダー左端の「メニュー」ボタンでメニューをオフにしても、左端のアイコン列（`#sidebarRail`, 幅 `54px`）は常に画面左端に残す。
  - メニューオフ状態で左端のアイコンをクリックすると、`#sidebarStage` が写真グリッドの上に **オーバーレイ展開（`is-overlay-open`）** され、もう一度同じアイコンを押すか写真グリッド側をクリックすると自動で引っ込む。

### 4.3 右インスペクタの `4:3` プレビュー & ファーストビュー EXIF サマリ
- **ミニビュー（`.inspector-preview-wrapper`）**:
  - アスペクト比は `aspect-ratio: 4 / 3; height: auto; max-height: none;` とし、内部の `<img>` は `object-fit: contain` で縦横どちらも見切れゼロで表示する。
  - プレビュー画像の上に重複する「波形」オーバーレイボタン（`.inspector-hist-toggle-btn`）は表示しない（ヘッダーの「波形」ボタンに一本化）。
- **常時表示クイックEXIFサマリ（`#inspectorQuickExif`）**:
  - 評価ボタン（`優 / 良 / 可 / 棄`）の直下・下部タブ（`タグ / 詳細情報 / マップ`）の直上に、タブを切り替えなくても一目で確認できる4行のEXIFサマリ（①撮影日時・解像度、②カメラ・レンズ名、③焦点距離・シャッター速度・F値・ISO・露出補正ピル）を常時表示する。

### 4.4 写真グリッド下部フローティングバーの廃止
- 写真選択時に画面下部中央へ出現していたフローティングバー（`#selectionFloatingBar`）は廃止（常時非表示）とし、写真グリッドの視界を一切遮らない設計とする。
- 単一・一括操作はすべて **右クリックコンテキストメニュー（`#contextMenu`）** および **右インスペクタ（一括編集モード）** で完結させる。

### 4.5 ダブルクリック → ビューワ（ライトボックス）即時起動の鉄則
- 写真グリッドのダブルクリック時（`click` × 2 → `dblclick`）に、2回目の `click` や `dblclick` で重複して `updateInspectorView()` を走らせてはならない。
- 一覧API（`/api/photos`）で既に `duplicate_count <= 1`（`photos.link_count <= 1`）かつ `has_xmp === false` と判明している写真では、インスペクタ表示時に不要な `/api/photo/{id}` 通信や二重再描画を行わない。
- `openLightbox(index)` はモーダル表示とメイン画像（キャッシュ済みサムネイル即時表示 ＋ フル解像度画像の非同期プリロード差し替え）を **0ms（同期フレーム）** で行い、1万枚超のフィルムストリップ構築（`renderFilmstrip`）は `requestAnimationFrame` へ遅延させ、かつ画面中央付近（`±18`枚）のみ `<img>` 要素をオンデマンド生成する。

### 4.6 ネイティブ `confirm()` / `alert()` の禁止 & カスタム確認モーダル統一規約（v1.2.2+）
- ブラウザ標準の `window.confirm()` および `window.alert()` は、Tetheract のダーク／ライトテーマやタイポグラフィから浮いてしまうため全面使用禁止とする。
- **確認ダイアログの統一 (`showConfirmModal`)**:
  - フォルダクリック時の差分更新確認（新規・消失子フォルダ、追加・削除・変更ファイルの内訳表示）、消失写真のリンク解除確認、各種削除・管理解除・AI再判定・XMP取込などの確認は、すべて `frontend/js/common.js` の `await showConfirmModal(options)`（`#commonConfirmModal`）を使用する。
  - `options` には `title`, `targetName`（`.raw-filename` クラスで翻訳対象外保護＆アクセント/危険色ハイライト）, `subPath`（モノスペースパス表示）, `detailRows`（色分けドット付きの内訳カード）, `description` / `descriptionLines`, `confirmText`, `cancelText`, `confirmVariant`（`'primary'` / `'danger'`）を指定できる。
  - キーボード操作として `Enter` で確定（ただし `danger` バリアント等でキャンセルボタンにフォーカスがある場合はキャンセル）、`Escape` でキャンセル（Captureフェーズで背後のモーダルへの伝播を遮断）をサポートし、`frontend/js/i18n.js` による日英リアルタイム翻訳に完全対応させる。
- **通知メッセージの統一 (`showToast`)**:
  - 処理完了・警告・エラーの通知には `alert()` を使わず、すべて `showToast(message, type, duration)` を使用する。

### 4.7 `Binder`（条件セット保存）・タグツリーオンデマンド入力・リンク消失バッジ（v1.4.0+）
- **`Binder`（条件セット保存専用ページ）のフラット構成**:
  - `Binder` ペインには「現在の絞り込み条件（`.preset-create-section` / `.preset-current-chips`）」＋ 保存フォームと「保存済みセット（`.preset-list-section`）」のみをフラットに配置し、外周の二重枠（Box-in-Box）を持たせない。
  - 表示対象（`すべての写真 / 接続中の写真 / 未接続の写真 / リンク消失の写真 / 未分類の写真 / 重複のある写真`）・形式（`すべての形式 / RAW / RAW+JPEG / JPEG / 調整済 / XMPあり`）・評価（`優 / 良 / 可 / 棄`）の切り替えはすべてメインツールバー中央の3大基本フィルタで行う。
- **子タグ作成フォームのオンデマンド表示化**:
  - 右インスペクタおよび設定モーダルのタグツリーエディタでは、常時表示の子タグ入力欄を置かず、各親タグの `+子` ボタンを押したときのみインライン入力欄を展開する。
- **ギャラリーカード上のリンク消失バッジ（`.unlinked-card-badge`）**:
  - リンク消失の写真（`photo.is_unlinked == 1`）には、写真カードのサムネイル右下（`bottom: 6px; right: 6px;`）にアンバー色のリンク切れSVGアイコンバッジを表示し、「すべての写真」の中で一覧していても一目で判別できるようにする。
- **フォルダ右クリックメニューの再スキャン整理と `[リンク消去]` ボタン**:
  - フォルダ右クリックメニューは「このフォルダを再スキャン（直下のみ）」と「再スキャン（子を含む）」（時間警告モーダル付き）に統一し、どちらも消失写真のリンク整理（`cleanup_orphans: true`）を自動で行う。
  - `[消失]` フォルダの右クリックメニューでは、最上部ヘッダーのフォルダ名右横にコンパクトな `[リンク消去]` ボタン（`#folderMenuHeaderUnlinkBtn`）を配置する。

### 4.8 4つのカラーテーマと2階建て属性構造（`data-scheme` ＆ `data-theme`）
- `frontend/js/common.js` の `applyTheme(scheme)` は、`<html>` 要素（`document.documentElement`）に以下の **2階建ての属性** を同時付与する：
  1. **`data-scheme`（4種類の個別パレット）**:
     - `tetheract-d`（Tetheract D (黄昏)：既定ダークテーマ、アクセント `#3b82f6`）
     - `tetheract-l`（Tetheract L (昼光)：ライトテーマ、アクセント `#2563eb`）
     - `sumi`（Hinomaru (夜墨)：純黒系ダークテーマ、アクセント朱色 `#e14d2a`）
     - `paper`（Hinomaru (白磁)：和紙系ライトテーマ、アクセント朱色 `#c83e1d`）
  2. **`data-theme`（明暗2種類のベース分類）**:
     - ダーク系2種（`tetheract-d` / `sumi`）のときは `data-theme="sumi"`
     - ライト系2種（`tetheract-l` / `paper`）のときは `data-theme="paper"`
- **CSS記述時の鉄則**:
  - 特定パレット固有の配色は `[data-scheme="..."]` で定義し、ライト系共通（`tetheract-l` と `paper` の両方）・ダーク系共通（`tetheract-d` と `sumi` の両方）の明暗調整は `[data-theme="paper"]` / `[data-theme="sumi"]` で記述する。
  - プロトタイプ時代の旧名称（`washi`, `urusi`, `dark`, `light`）は存在しないため、CSSセレクタに使用してはならない。

## 5. ドキュメント & リリースノート編集規約 (OSS Editorial Standards)

`README.md`, `README_EN.md`, `RELEASE_NOTES.md`, `docs/release_notes/RELEASE_NOTES_v*.md` を執筆・更新する際は、以下の「脱・AIポエム／脱・芋ドキュメント」ルールを厳守する：

1. **見出し・箇条書き先頭の絵文字スパム禁止**:
   - `### 🚀 特徴` `- ✨ **高速表示**: ...` のような全行絵文字プレフィックスは全面禁止。
2. **太字の壁（Bold-Text Wall）と感嘆符（`！`）の禁止**:
   - 1文の中に太字を何箇所も入れたり、技術説明の文末に `！` を付けて煽ったりしない。
3. **テーブルと構造化リストの活用**:
   - 機能一覧、キーボードショートカット、動作要件、ディレクトリ構成は散文ではなく Markdown テーブルで端正に整理する。
4. **GitHub Alerts の節度ある使用**:
   - `> [!NOTE]` や `> [!IMPORTANT]` はドキュメント内で本当に重要な箇所（差分アップデートの注意事項など）に限定して使用する。
