# ポータブルストレージ & パス追跡パターン

## 1. 課題と背景

Photo Manager をUSBメモリやポータブルSSDに丸ごと保存して複数台のPC（自宅PC、ノートPC、職場PCなど）で持ち運ぶ場合、以下の問題が発生する。

1. **ドライブレターの変動**:
   あるPCでは `D:` ドライブとしてマウントされたUSBが、別のPCでは `E:` や `F:` になる。
2. **データベースに記録されたフルパスの無効化**:
   スキャン時に `D:\Photos\IMG_0001.JPG` として SQLite に登録された場合、ドライブ文字が変わると `os.path.exists()` が `False` になり写真が開けなくなる。
3. **大容量元写真の分離持ち運び**:
   サムネイルとタグ付けデータ（数GB）だけを高速なUSBに入れ、重いRAW元画像（数百GB）はPC側の内蔵HDDや別ドライブに置いたまま鑑賞・整理したいというニーズ。

---

## 2. 解決アーキテクチャ

### (1) Windows API によるボリューム識別 (`server/volume_info.py`)
ドライブ文字は一時的な割り当てに過ぎないため、物理ドライブの固定識別子として **ボリュームシリアル番号 (VSN: Volume Serial Number)** を利用する。
Python標準の `ctypes` 経由で Windows API `GetVolumeInformationW` を呼び出し、外部DLL依存なしでVSNとボリュームラベルを取得する。

```python
# VSNの16進数文字列（例: "A1B2C3D4"）を取得
volume_info = get_volume_info(path)
```

スキャン時に `volumes` テーブルおよび `scan_roots` テーブルに VSN を記録することで、次回接続時にドライブ文字が変わっていても「同じストレージである」と判定・再紐付けが可能。

### (2) 動的パス解決 (`server.scanner.resolve_portable_path`)
写真ファイルへのアクセスが発生した際、以下の優先順位で動的にパスを探索する：

```text
[DBに保存された stored_path]
       │
       ▼
 [そのまま存在する？] ──(Yes)──> 解決成功 (オンライン)
       │ (No)
       ▼
 [現在のUSBドライブ上に同一相対パスがある？] ──(Yes)──> 解決成功 (オンライン)
       │ (No)
       ▼
 [プロジェクト直下の "photos/" 内にある？] ──(Yes)──> 解決成功 (オンライン)
       │ (No)
       ▼
 未接続（オフライン）判定
```

### (3) カタログ単体持ち歩き機能（オフライン閲覧）
- サムネイルはすべて SQLite（`.cache/library.db`）に BLOB 格納されているため、元画像ファイルが手元にない状態（オフライン）でも、高速な一覧表示・拡大プレビュー・タグ付け・星評価・検索が完全に機能する。
- オフライン写真は画面上に控えめに「未接続」バッジが表示され、元画像が存在しないことによるクラッシュを防止している。
