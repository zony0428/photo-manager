# タグツリー並び順制御・2ペイン「タグツリーエディタ」＆一括タグ操作設計 (v2.11 〜 v2.43)

本ドキュメントは、Photo Manager の各種タグツリー表示におけるソート順制御（枚数順トグル＆名前順ルール選択）、設定画面内の専用「🌳 タグツリーエディタ」（ドラッグ＆ドロップ階層変更・祖先タグ安全同期）、およびインスペクタ一括タグ設定のUX・整合性設計に関する技術ノウハウ・知見をまとめたものである。

---

## 1. タグツリーの並び順制御（`📊 枚数順` トグル ＆ 名前順4ルール）

### 背景・課題
- イベントや年・月でタグを管理する際（例: `24-○×▲`, `2410-abcd`, `25-XYZ`）、JavaScript の `localeCompare(..., { numeric: true })`（自然順ソート）を固定適用すると、先頭の数値塊が「24 < 25 < 2410」と比較され、24年10月のタグが25年の後ろに飛んでしまう問題があった。
- 一方で「シンプルに写真枚数が多いタグを上に並べたい」というニーズと、「普段の名前順は文字コード順（または自然順）の好みで固定したい」というニーズの両立が求められた。

### 解決策 (`buildTagTree` in `frontend/js/sidebar_filters.js`)
1. **左サイドバー「`📊 枚数順`」ワンクリックトグル (`#tagSortByCountToggleBtn`, `state.tagSortByCount`)**:
   - **ON（点灯時）**: 各階層の子ノードを **写真枚数の多い順 (`(b.count || 0) - (a.count || 0)`)** を最優先でソートし、枚数が同じ場合は設定画面の名前順ルールで並べる。
   - **OFF（消灯時）**: 設定画面（`⚙️ 設定`）の `#settingTagSortModeSelect` で保存された名前順ルール（`localStorage: pm_tag_sort_mode`）に従って並べる。
2. **名前順4ルールの選択保存 (`state.tagSortMode`)**:
   - `'lexical'`（デフォルト）: 文字コード・辞書順昇順（`numeric: false`）。`24-○×▲` → `2410-abcd` → `25-XYZ` の順に直感的に並ぶ。
   - `'lexical_desc'`: 文字コード・辞書順降順。
   - `'natural'`: 数値自然順昇順（`numeric: true`）。`第1回` → `第2回` → `第10回` の順に並ぶ。
   - `'natural_desc'`: 数値自然順降順。

### 適用範囲
`buildTagTree` を共通基盤としている以下のすべてのツリーに即時反映される：
1. **左サイドバーのタグフィルタツリー** (`renderTagList`)
2. **右インスペクタ（単一／一括）のクイックタグツリー** (`renderInspectorQuickTree`)
3. **設定モーダル右ペインの「🌳 タグツリーエディタ」** (`renderSettingsTagTreeEditor`)
4. **右クリックメニュー／下部フローティングバーのタグツリー**

## 2. 3ペインの役割分離と専用「🌳 タグツリーエディタ」(v2.43)

### 誤操作防止のためのUI責務分離
1. **左サイドバー（`#tagList`）**: **100% 純粋なフィルタリング（絞り込み）専用**。リネームや削除ボタンを一切置かず、クリックで `[+]` 含む ➜ `[-]` 除外 ➜ 解除 のみに集中させる。
2. **右インスペクタ（`#inspectorQuickTree` / `#batchQuickTree`）**: **日常の写真へのタグ付与（`+追加` / `✓付与済`）と素早い子タグ追加（`+子`）専用**。選別作業中のうっかり操作を防ぐため、インスペクタからはリネーム（`✏`）や全体削除（`🗑️`）を排除し、設定画面を開く **`⚙️ ツリー編集`** ショートカットボタンを配置。
3. **`⚙️ 設定 ＆ タグツリーエディタ` モーダル右ペイン（`#settingsTagTreeContainer`）**: **タグ階層の構造変更・リネーム・全体削除の専用モード**。
   - **ドラッグ＆ドロップ階層移動**: タグ行（`⋮⋮`）を別のタグへドロップすると、確認ダイアログのうえでその親タグの配下（`targetPath/leafName`）へサブツリーごと移動する（自身や自身の子孫へのドロップは自動拒否）。
   - **ルート（最上位階層）への独立移動**: 子タグを上部のドロップゾーン（`#settingsTagRootDropZone`）へドロップすると、最上位ルート（`leafName`）へ独立移動する。
   - **0枚の空タグ・親フォルダ作成 (`tag_definitions` テーブル)**: `server/database/schema.py` に `tag_definitions` テーブルと `POST /api/tags/create` を設け、写真に1枚も付与していない状態でもツリーエディタ上で新しいルートタグや子タグを作成・永続化できる。
   - **インラインリネーム (`✏`) ＆ 全体削除 (`🗑️`)**: 全体削除時は必ず `#deleteTagModal`（影響枚数表示＋OK/NG確認）を経由する。

## 3. 階層移動時の祖先タグ安全同期アルゴリズム (`rename_tag` in `server/database/tags.py`)

Photo Manager の `photo_tags` テーブルは「祖先ノード独立保存方式」（写真に `A/B` を付けると `A` と `A/B` の2行が保存される）を採用しており、1枚の写真が `A/B` と `A/C` を同時に持つことができる。

タグ `old_tag`（例: `A/B`）を `new_tag`（例: `D/B`、あるいはルート `B`）へ移動・リネームする際、`rename_tag()` は単なる文字列置換ではなく以下の4ステップをトランザクション内で実行する：
1. **循環移動防止**: `new_tag.startswith(old_tag + "/")`（自分自身の子孫への移動）を `ValueError` でブロック。
2. **対象タグおよび子孫タグの書き換え**: `old_tag` および `old_tag/*` を `new_tag` / `new_tag/*` へ更新（重複時は既存レコードを優先してマージ）。
3. **新しい祖先タグの自動補完**: 移動後のパス `new_tag` が持つ新しい祖先（例: `D`）を、対象写真すべてに `INSERT OR IGNORE` で自動付与。
4. **不要になった古い祖先タグの条件付きクリーンアップ**: 移動によって外れた古い祖先（例: `A`）について、**その写真が他の `A/*` タグ（例: `A/C`）を1つも持っていない場合のみ** `A` を削除し、`A/C` を持っている写真では `A` をそのまま維持する。

## 4. インスペクタ一括タグ設定のUX・操作完了時の選択自動解除

複数写真選択時の一括タグ設定（`POST /api/photos/batch-tags`）完了後は、以下のライフサイクルを実行する：
- **`clearSelection()`**: 選択を解除してグリッドの選択枠およびフローティングバーを消去し、インスペクタを通常表示に戻す。
- **`await Promise.all([fetchPhotos(), fetchTags()])`**: 現在適用中の全フィルタ条件を再クエリし、サイドバーのタグ件数バッジを最新化する。
