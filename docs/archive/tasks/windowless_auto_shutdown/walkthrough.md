# コマンドプロンプト非表示起動 & 自動シャットダウン機能の確認

コマンドプロンプト（黒い画面）を表示させずに Photo Manager を起動し、ブラウザを閉じた際にバックグラウンドの Python プロセスが自動で安全に終了する仕組みを実装しました。

---

## 主な変更点

### 1. ランチャーの非表示起動対応
- [start.bat](file:///r:/photo-manager/start.bat)
  - ポータブルPython、仮想環境（venv）、システムPythonの各環境から **`pythonw.exe`**（GUI用のコンソール非表示版Python）を検出。
  - `pythonw.exe` が見つかった場合、`start "" "!PYW_EXE!" "%~dp0run.py"` を用いてバックグラウンドで起動し、**バッチファイル自身（黒いコマンド画面）は瞬時に自動終了（約0.2秒で消滅）** します。
  - `pythonw.exe` がない古い環境では、従来のコンソール付き起動（`python.exe`）に自動フォールバックします。
  - 日本語コメントによる文字コード誤認（CP932/UTF-8不整合）を防ぐため、ASCIIクリーン記述に統一しました。

### 2. バックエンドの自動シャットダウン機構
- [server/heartbeat.py](file:///r:/photo-manager/server/heartbeat.py) (新規作成)
  - フロントエンドからのハートビート信号を定期監視する専用モジュールを新設。
  - **初回接続タイムアウト (60秒)**: 起動直後、ブラウザが立ち上がるまでの準備時間を十分に確保。
  - **通常切断タイムアウト (12秒)**: ブラウザが閉じられ、ハートビートが途絶えてから約12秒で自動的に Uvicorn サーバーをクリーン終了（SIGINT通知）。
  - 万が一ハングした場合のフェイルセーフ強制終了スレッド（3秒猶予）も備え、ゾンビプロセスの残存を完全に防止。
- [server/app.py](file:///r:/photo-manager/server/app.py)
  - `lifespan` 起動処理内でハートビート監視スレッドを開始。
  - `POST /api/heartbeat`（生存確認の記録）と `POST /api/shutdown`（手動シャットダウン要求）を追加。
- [run.py](file:///r:/photo-manager/run.py)
  - `pythonw.exe` 実行時（コンソール入出力がない状態）に Uvicorn や Python がクラッシュしないよう、安全にログを `server.log` にリダイレクトする仕組みを追加。
  - 既にサーバーが稼働中に再度 `start.bat` が実行された場合の **二重起動防止処理** を追加（ポート衝突エラーにならず、ブラウザ画面を前面に開くだけで即座に終了）。

### 3. フロントエンドのハートビート定期送信
- [frontend/js/app.js](file:///r:/photo-manager/frontend/js/app.js)
  - `initHeartbeat()` 関数を追加し、アプリ起動後 **3秒間隔** で `/api/heartbeat` をバックグラウンド送信。
  - タブの切り替えやウィンドウの再フォーカス時（`visibilitychange`, `focus`）にも即座にハートビートを送信するよう最適化。

## 検証結果

### 1. ハートビート監視と自動停止の単体検証
- `scratch/test_heartbeat.py` を実行：
  - タイムアウト発生時に `[INFO] 自動シャットダウンを実行します (理由: ブラウザ切断（ハートビート途絶）を検知しました)` がトリガーされ、シグナルによりプロセスが安全に停止することを確認。
- `scratch/test_initial_timeout.py` を実行：
  - 初回起動後に一度もブラウザ接続がなかった場合、指定秒数で安全にプロセスが終了することを確認。

### 2. API疎通と非同期終了の検証
- `scratch/test_api_heartbeat.py` を実行：
  - `/api/heartbeat` が `{"status": "ok"}` を即時返却。
  - `/api/shutdown` 呼び出し時、HTTP 200レスポンスをクライアントに返し終えた後にバックグラウンドスレッドでシャットダウン処理が実行されることを確認。

### 3. `start.bat` によるエンドツーエンド起動 & 自動停止検証
- `start.bat` を実行：
  - コンソール画面がコンマ数秒で閉じ、バックグラウンドで `pythonw.exe` が立ち上がり、Edge/Chrome のアプリウィンドウが起動。
  - 稼働ログが `server.log` に正常に出力されることを確認。
  - ブラウザを閉じてから約12秒後に、バックグラウンドの Python プロセスが自動で消滅（正常終了）することを確認。

## 追加修正（画像・DBが読み込まれなかった原因と解消）

### 原因の特定
- [app.js](file:///r:/photo-manager/frontend/js/app.js) の 1652行目に余分な閉じ括弧 `}` が紛れ込んでおり、ブラウザ側で `SyntaxError: Unexpected token '}'` が発生していました。
- これにより JavaScript の実行全体が途中でストップし、写真一覧取得（`/api/photos`）やハートビート送信（`/api/heartbeat`）が動かず、画面が読み込み中のままになっていました。

### 対応内容
1. `app.js` の余分な閉じ括弧を削除し、構文エラーを解消。
2. ブラウザのキャッシュを確実に破棄して最新のスクリプトを読み込ませるため、[index.html](file:///r:/photo-manager/frontend/index.html) 内のスクリプトタグを `v=heartbeat_v1` に更新。
3. 初回起動時のブラウザ立ち上がり待機時間を考慮し、[server/heartbeat.py](file:///r:/photo-manager/server/heartbeat.py) の `INITIAL_TIMEOUT` を 300秒（5分）に延長。
4. ブラウザ（Headless Edge）で実際にページを開き、全801枚の写真およびサムネイルが正常にロードされることを確認しました。

## 実際の使い方

1. **起動**:
   - これまで通り **`start.bat` をダブルクリック** します。
   - 一瞬だけ黒い枠が出ますが、0.2秒ほどですぐに自動でスッと消えます。
   - 直後にブラウザ（Edge/Chrome のアプリウィンドウ）が立ち上がります。
2. **利用中**:
   - 黒い画面は一切邪魔になりません。ブラウザだけで快適に操作できます。
3. **終了**:
   - **ブラウザの「×」ボタンを押して閉じるだけ** です。
   - 約12秒後にバックグラウンドのサーバープロセスが自動で安全に終了します。
