## 2. 目標UI（左ペイン「📁 フォルダ」タブ）

```text
📁 フォルダ                    [🤖自動タグ ON] [⚙]
⭐ ショートカット
   🖼️ ピクチャ                         (128)
   📄 ドキュメント                      ●
   🖥️ デスクトップ
💻 接続中のドライブ
 ▶ 💿 C: (Windows)                      ●   ← 配下に管理フォルダあり
 ▼ 💿 D: (Photo)                     (2,140)
    ▶ 📂 2025_旅行                    (1,320)  ← 管理中: 強調
      📁 work                                  ← 未登録: 淡色
      📁 tmp            [除外]                 ← 除外: 打ち消し線
───────────────────────────────────
💾 未接続（キャッシュのみ）
 ▶ 💾 SSD-Portable（前回 E:）          (530)
   [スキャン進捗バー: 42 / 300 枚 …]
   [パスを直接入力して追加・スキャン ____________ ▶]
```

- **管理中**: 太字＋アクセント色＋枚数。**配下に管理フォルダがある祖先**には小さな印（●）を付け、深い階層でも辿れるようにする。
- **未登録**: 淡色。**除外**: 打ち消し線＋`除外`バッジ（既存CSSを流用）。
- **未接続ドライブ**: DBの情報だけでツリーを組む（実フォルダは走査しない）。サムネイル閲覧・絞り込みは可能。

## 3. 設計

### 3.1 バックエンド

| 変更 | 内容 |
|---|---|
| 新規 `GET /api/folder-tree/roots` | `shortcuts` / `drives`（接続中）/ `offline_volumes`（未接続）を返す。各要素に `total`（配下の写真総数）と `has_managed` を付与 |
| 新規 `GET /api/folder-tree/children?path=` | 指定フォルダ直下の子を**遅延取得**。`os.scandir` の結果と、DBにだけ存在する子（消えた/未接続）をマージし、`status`(managed/unmanaged/ignored)・`count`・`total`・`is_missing` を返す |
| 集計SQL | 配下件数は `_directory_filter_sql(path, recursive=True)` の範囲で `GROUP BY directory_path` を1回だけ実行し、Python側で直下の子ごとに合算する（全件取得・相関サブクエリは使わない） |
| 未接続の判定 | ドライブ文字が接続されていても、**現在のボリュームシリアルと `photos.volume_serial` が違えば未接続扱い**（USBの文字使い回しで別ドライブを誤表示しないため） |
| `POST /api/scan` 拡張 | 「リフレッシュ」用に、消えたファイルの削除を**配下フォルダまで**行えるようにする（`cleanup_missing_photos_in_folder` に `recursive` 引数を追加） |
| `GET /api/photos` 拡張 | `exclude_folder` を追加（`AND NOT (範囲条件)`）。左クリック2回目の除外絞り込み用 |
| 流用 | `/api/folders/ignore`・`DELETE /api/folders`・`/api/folders/open`・`/api/ai/tag-folder` はそのまま使う |

### 3.2 フロントエンド

- 新規 `frontend/js/folder_tree.js` に、ツリー描画・遅延展開・右クリック・左クリック切替をまとめる（現在 `app.js` 3,252行に散在しているフォルダ関連を移す）。
- `executeScan()` を**モーダルのDOMに依存しない形**に作り直し、進捗はフォルダタブ下部の進捗バー＋トーストで表示する。
- 既存の `buildFolderTree()` は未接続ドライブのツリー生成に流用する。

### 3.3 左クリックの切替

| クリック | 状態 | 表示 |
|---|---|---|
| 1回目 | そのフォルダ（配下含む）だけを表示 | `📁 2025_旅行` |
| 2回目 | そのフォルダ（配下含む）を**除外**して表示 | `🚫 除外: 2025_旅行` |
| 3回目 | 解除 | すべての写真 |

▶ をクリックすると展開のみ（絞り込みは変えない）。

### 3.4 右クリックメニュー（状態ごと）

| メニュー | 管理中 | 未登録 | 除外 | 未接続 |
|---|:-:|:-:|:-:|:-:|
| 🔄 スキャン（直下のみ／配下も含む） | ○ | ○（＝管理に追加） | ○（除外を解除して追加） | × |
| ♻️ リフレッシュ（再スキャン＋消えたファイルをDB削除・配下含む） | ○ | – | – | × |
| 🤖 AIタグ付け | ○ | – | – | ○ |
| ➖ 管理から外す（DB登録解除） | ○ | – | – | ○ |
| 🚫 管理対象外にする／↩️ 除外を解除 | ○ / – | ○ / – | – / ○ | – |
| 📁 エクスプローラーで開く | ○ | ○ | ○ | × |

### 3.5 安全策

- **リフレッシュは接続中のフォルダだけ**で実行可能（未接続のまま実行すると全件削除になるため。`scan_directory` も実在しないフォルダは拒否する）。実行前に確認ダイアログを出す。
- **ドライブ直下・ホームフォルダのスキャン**は件数が膨大になり得るので確認ダイアログを出す。
- 切断中のネットワークドライブで `os.path.isdir` が数秒止まる問題を避けるため、ドライブ一覧は `GetDriveTypeW` で種別を取り、ネットワークドライブの存在確認は展開時まで遅らせる。
- 破壊的操作（リフレッシュ・管理から外す）の検証は、`scratch/perf/bench.py` と同じ方法で**本番DBの複製**に対して行う。

## 5. 決定事項（2026-10-08 ユーザー回答）

1. **ショートカット**: ピクチャ／**ドキュメント**／デスクトップ（「マイドライブ」は誤記）。
2. **DB最適化／バックアップ**: フォルダタブ見出しの ⚙ から開く小さな「DBメンテナンス」画面へ移設。
3. **スキャン後AI自動タグ**: フォルダタブ見出しのON/OFF切替（localStorage に記憶）。
4. **パス直接入力**: フォルダタブの**一番下**に配置。
5. **ツールバー「フォルダ管理」ボタンとモーダル**: 新しいフォルダタブで動作確認が取れるまで残し、確認後に削除（フェーズ4はユーザー確認後に実施）。
6. **名称変更（実施済み）**: ヘッダー「写真追加」→「📥 取り込み」、右クリック／下部バー「送る (import)」→「📤 書き出し準備」。実フォルダ名 `import` / `uploads` は変更しない。
7. **関連する不具合修正（実施済み）**:
   - 「ライブラリから削除」ボタンが無反応だった問題（`deleteSelectedPhotos` 未定義）を修正。`POST /api/photos/batch-delete` を新設（DBのみ削除、スタック表示中はスタック内の写真も含む、削除後にスタックを再計算）。
   - 下部バーの評価設定が★5〜★0（0〜5）になっていた問題を、優(2)／良(1)／可(0)／棄(-1) に修正。`batch-rate` APIで範囲外の値を400で拒否。
