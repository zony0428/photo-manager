# ドキュメンテーション & 操作マニュアル規約 (Documentation Standards)

本プロジェクト（Photo Manager）において、機能の追加・改善とドキュメンテーションの鮮度を完全に一致させるための基本規約を定義する。

---

## 1. ドキュメント同期の鉄則

1. **仕様変更時のマニュアル同時更新義務**:
   - 新規機能の追加、UIレイアウトの変更、キーボードショートカットの変更・追加を行った場合、**必ず同コミットまたは連続する改修の中で `MANUAL.md` およびアプリ内ヘルプ（`frontend/index.html` の `#helpModal`）を更新**しなければならない。
   - 「コードだけ変更してマニュアルは後回し」は厳禁とする。

2. **アプリ内ヘルプモーダルとの一貫性**:
   - アプリ内ヘルプ（`?` / `F1` キーで起動）は、ユーザーが作業を中断することなく瞬時に参照できるチートシートである。
   - `MANUAL.md`（詳細版）とアプリ内ヘルプ（要約版）の間でショートカットキーや機能仕様の食い違いが生じてはならない。

3. **配布パッケージ（`build_dist.bat`）への同梱維持**:
   - USB配布用パッケージ（`dist` および `dist_update` フォルダ）に `MANUAL.md` と `RELEASE_NOTES.md` が必ずコピーされるよう、`build_dist.bat` の設定を維持・確認する。

---

## 2. リリースノート自動生成・保存ルール (Release Notes Standard)

バージョン番号を更新してリリースを行う際は、チャット上の案内だけでなく、**必ずプロジェクト配下のファイルとしてリリースノートを生成・保存**する。

1. **保存場所とファイル構成**:
   - **バージョン別アーカイブ**: `docs/release_notes/RELEASE_NOTES_v<VERSION>.md`（例: `docs/release_notes/RELEASE_NOTES_v2.43.md`）
     - GitHub Releases の投稿フォームにそのままコピー＆ペーストできる完全版テキストとして保存する。
   - **ルート直下の統合リリースノート**: `RELEASE_NOTES.md`（プロジェクトルート直下）
     - 最新バージョンのリリース内容を先頭に配置し、過去バージョンの更新履歴（Changelog）もあわせて収録する。`build_dist.bat` により `dist/` および `dist_update/` にも自動同梱される。

2. **リリースノートの必須記載項目**:
   - **メタ情報**: `Tag`（例: `v2.43`）および `Title`（主な目玉機能が一目で分かるタイトル）。
   - **アップデート方法のご案内（差分版 / フル版の使い分け）**:
     - 既存ユーザー向けに、軽量差分パッケージ **`PhotoManager_v<VERSION>diff.zip`** を解凍して既存フォルダへ上書きするだけで 1秒でアップデート完了すること（`cache/`・`storage/`・`models/`・`python/` は維持されること）を明記する。
     - 新規導入ユーザー向けに、フルパッケージ版 **`PhotoManager_v<VERSION>.zip`** の利用を案内する。
   - **更新内容（日本語 ＆ 英語の2言語併記）**:
     - 新機能（What's New）、パフォーマンス改善、UI反応性・不具合修正（Bug Fixes）を分かりやすく整理して記載する。

---

## 3. 記述・表現ルール

1. **言語**:
   - すべて**日本語**で記述する。
   - キーボードのキー名は `<kbd>Enter</kbd>` や `**`Space`**` のように統一する。

2. **親切さと専門性の両立**:
   - RAW現像、EXIFメタデータ、露出ブラケット、バースト連写、CLIP Vision AIなどの専門用語には、初心者が直感的に理解できる補足説明を添える。
   - 代表的なユースケース（「休日の撮影旅行から帰ってきた後の仕分け」「USBで実家に持っていく場合」等）を意識した実践的な文面とする。

3. **ヒント & 注意事項の明記**:
   - 削除・非表示の挙動（「棄」は画面から消えるがDBや元ファイルは安全等）など、ユーザーが不安を覚えやすいポイントには「💡 ヒント」や「※ 注意」を必ず記載する。
