# 操作マニュアル & ヘルプ保守スキル

Photo Manager は、Picasa / Tiat ライクな高速選別、ローカルAI自動タグ付け、USBポータブル運用など、
多彩かつ直感的な機能を備えています。

ユーザーが迷わず快適に利用できるように、**コードの変更と操作マニュアル（外部Markdown & アプリ内ヘルプ）を常に100%同期させる**ためのワークフローをここに定義します。

---

## 1. 保守対象のドキュメント構成

| 対象 | ファイルパス | 主な役割 |
|---|---|---|
| **外部マニュアル** | `MANUAL.md` (ルート) | 全機能網羅の完全マニュアル。GitHub閲覧およびUSB同梱用 |
| **リリースノート (統合)** | `RELEASE_NOTES.md` (ルート) | 最新リリース内容と過去の更新履歴。GitHub閲覧および配布パッケージ同梱用 |
| **リリースノート (各版)** | `docs/release_notes/RELEASE_NOTES_v<VERSION>.md` | バージョン別の GitHub Releases 投稿用テキスト（差分版/フル版案内・日英併記） |
| **アプリ内ヘルプ** | `frontend/index.html` (`#helpModal`) | アプリ使用中に `?` / `F1` またはボタンで即座に参照できるチートシート |
| **ヘルプスタイル** | `frontend/css/style.css` | ヘルプモーダルのレイアウト・タブ・キートップ（kbd）の装飾 |
| **USB起動ガイド** | `README_USB.md` (ルート) | USBメモリへのコピー・起動・PC間持ち歩きに特化したガイド |
| **配布バッチ同梱** | `build_dist.bat` | 配布用パッケージ生成時に `MANUAL.md` や `RELEASE_NOTES.md` が正しくコピーされることの保証 |

---

## 2. マニュアル更新のトリガー（いつ更新するか）

以下の改修を行った際は、**コード改修と同時に必ずドキュメントも更新**します：

1. **ショートカットキーの追加・変更**:
   - 例: テンキー仕分けの変更、十字キー移動の再設計、新規ショートカットの追加
2. **新規機能の追加**:
   - 例: スライドショー、フィルタープリセット、AIモデルの変更、新しいエクスポート機能
3. **UIレイアウト・画面構成の変更**:
   - 例: 新しいペインやタブの追加、表示モードの追加
4. **USB・ポータブル運用の仕様変更**:
   - 例: フォルダ構成の変更、新ファイル形式のサポート、キャッシュ仕様変更

## 3. 同期更新の 4ステップ・ワークフロー

### ステップ 1: 変更点の抽出
コード変更時に、ユーザー体験に関わる以下の要素を整理する：
- 何ができるようになったか？（目的・メリット）
- どの画面でどう操作するのか？（マウス操作、キーバインド）
- どのような表示・変化が起こるか？（バッジ、アニメーション、非表示化）

### ステップ 2: `MANUAL.md` の更新
- 該当する章（「3. 爆速・写真選別」「4. ライトボックス」「8. ショートカット一覧」等）に具体的な操作手順を追記。
- キーボード操作は `**`1`**` のように太字コード記法で統一。
- 表（テーブル形式）で一覧性を高める。
- よくある疑問や注意点は「💡 ヒント」コールアウトを活用。

### ステップ 3: アプリ内ヘルプモーダル（`frontend/index.html`）の更新
アプリ内ヘルプは画面を見ながらサッと確認する「クイックリファレンス」です。
- `#helpTab-shortcuts` のテーブルに新キーバインドを反映（`<kbd>` タグを使用）。
- 該当するタブ（`#helpTab-workflow`, `#helpTab-lightbox` 等）の解説カード（`.help-card`）を更新。
- 文字数は要点を簡潔にまとめ、視認性を重視する。

### ステップ 4: 配布設定・バージョン・リリースノートの確認
- `build_dist.bat` で `MANUAL.md` および `RELEASE_NOTES.md` が `dist/`・`dist_update/` にコピーされる設定が維持されているか確認。
- 改修時は `VERSION` ファイル内の最終更新日時（`Updated: YYYY-MM-DD HH:MM`）を更新し、検証確認が完了してGitコミットを行うタイミングでバージョン番号を `0.01` カウントアップ（またはユーザー指定値へ変更）する。
- リリース時は `docs/release_notes/RELEASE_NOTES_v<VERSION>.md`（GitHub Releases コピペ用・差分ZIP/フルZIP案内付き・日英併記）を生成し、ルートの `RELEASE_NOTES.md` にも最新バージョンを追記してから `build_dist.bat` を実行する。

## 4. 記述スタイルガイドライン

- **キー表記**:
  - HTML内: `<kbd>1</kbd>`, `<kbd>Shift</kbd> + <kbd>Click</kbd>`, `<kbd>↑</kbd>`
  - Markdown内: `**`1`**`, `**`Shift + Click`**`, `**`↑`**`
- **アイコンと絵文字**:
  - 視線誘導のために見出しやバッジに絵文字を適切に配置（例: `🏅 優`, `⭐ 良`, `🗑️ 棄`, `🔍 ズーム`, `⚡ 連写`）。
- **専門用語の平易化**:
  - EXIF、AEB（露出ブラケット）、ゼロショットAI、WALモード等の専門用語は、初心者でも理解できるように日常的な言葉（「カメラの撮影情報」「露出を変えて連続撮影」「写真の自動判別」等）を併記する。
